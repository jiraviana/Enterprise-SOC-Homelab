# Detection Engineering Case Study: MITRE ATT&CK T1562.001

**Project Status:** Ongoing Development

## Detection Overview

This case study documents a custom Wazuh detection designed to identify PowerShell command patterns associated with attempts to disable Microsoft Defender real-time protection.

| Field | Details |
|---|---|
| MITRE ATT&CK Technique | T1562.001 — Impair Defenses: Disable or Modify Tools |
| Wazuh Rule ID | 100109 |
| Rule Severity | Level 12 |
| Log Source | Windows PowerShell Script Block Logging |
| Windows Event ID | 4104 |
| Endpoint | Windows11-Lab |
| Validation Date | October 21, 2026 |
| Detection Status | Validated using a controlled test string |

## Detection Objective

Identify suspicious PowerShell script content referencing the Microsoft Defender configuration command `Set-MpPreference` with `-DisableRealtimeMonitoring` enabled.

## Detection Methodology

1. Configure a custom Wazuh rule to identify the relevant PowerShell command pattern.
2. Collect Windows PowerShell Event ID 4104 telemetry through the Wazuh agent.
3. Generate a controlled PowerShell test string containing the suspicious command pattern.
4. Review Wazuh security events for the custom rule ID.
5. Verify the agent, rule severity, MITRE mapping, and alert description.

## Validation Results

A matching alert was observed in Wazuh during the controlled test.

- Rule ID: 100109
- Alert level: 12
- Windows Event ID: 4104
- MITRE mapping: T1562.001
- Endpoint: Windows11-Lab

**Important limitation:** This test confirms that the detection identified the command pattern. It does not demonstrate that Microsoft Defender was actually disabled.

## Investigation Considerations

An analyst investigating a similar alert should review the complete PowerShell script block, execution context, associated process activity, user account, device security state, and nearby events to determine whether the behavior represents authorized administration, a benign test, or potential defense evasion.

## Future Improvements

- Test additional command variations and potential bypasses.
- Evaluate false positives and detection coverage.
- Correlate PowerShell telemetry with process creation events.
- Document additional validation evidence and investigation findings.
